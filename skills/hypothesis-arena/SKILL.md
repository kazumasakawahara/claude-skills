# 仮説競争シミュレータ（hypothesis-arena）

## このスキルが解く問題

deliberation-sim が「決める道具」なら、これは「知る道具」である。一人で調べると、最初に気に入った仮説を支持する文献ばかりが集まり、読書量が増えるほど確信だけが強まる。対策は T.C. チェンバレンの**複数作業仮説法**と J.R. プラットの **Strong Inference**：仮説を複数並走させ、**どの観測・文献がどの仮説を殺すか**を先に決めてから読む。漫然と関連文献を積むのではなく、**仮説を殺すために読む**。

素朴に「仮説を並べて比較する」だけでは必ず失敗する。四つの失敗と対策がこのスキルの本体である。

| 失敗 | 症状 | 対策 |
|---|---|---|
| 確証バイアスの再生産 | 本命仮説を支える文献ばかり集まる | 仮説ごとに擁護者人格を分け、判別読書は「他説を殺せるか」で設計する |
| ペット仮説の不死身化 | どんな証拠が出ても解釈で生き延びる | 立論時に**自滅条件**（この証拠が出たら自説は死ぬ）を宣言させ、満たされたら強制淘汰 |
| 更新の演出化 | 「なるほど確信度を下げます」が礼儀として起きる | 台帳の証拠エントリと紐づかない確信度変更を無効化する |
| 言葉の争いの見逃し | 定義の違いだけで対立しているのに実質的論争に見える | H0 で中核用語の操作的定義を固定し、定義差なら「言語的論争」と判定して分岐する |
| 擁護者の同質化 | 同じ書き手が全仮説を順に擁護するので、後の擁護者ほど前の文章に寄り、本命へ予定調和で収束する | H1 立論は仮説ごとに**相互非参照**で書かせる。1つの会話で順に書く場合は台帳に「非独立立論」と記し、サブエージェントが使える環境では仮説ごとに独立させる（→ PROTOCOL.md H1、環境固有の設定） |

## 起動する / しない

**起動する**：真偽・原因・優劣が争われており、複数の説明が成り立ちうる問い。「なぜ」「本当か」「どちらの説が」の形をした問い。

**起動しない**：
- 「〜すべきか」「どちらを選ぶか」の意思決定 → `deliberation-sim` へ。逆に、本スキルの裁定者が「これは事実問題でなく価値選択だ」と判定した場合は deliberation-sim へ送り返す（相互接続点）
- 単発の事実確認（検索して答えれば済むもの）
- 文献の取得・変換そのもの → 文書取得・変換ツールの管轄。本スキルは「**何を読むか**」を決めるまでが仕事
- 医療・法律の個別判断（一般論としての論争の検討はよいが、特定個人の治療・事件への断定はしない）

## 全体の流れ

```
手順0  問いの定式化（操作的定義の固定・判別層の仮判定・台帳の新規作成 or 読込）
H0    仮説生成（3〜5本、相互排他性チェック、擁護者人格の付与、ユーザー承認）
H1    立論（各仮説の文献予測＋自滅条件＋初期確信度を宣言）
H2    相互攻撃（steelman義務、証拠は階層つきで提示）
H3    判別課題の設計（裁定者が期待情報量順の判別読書リストを出力）← 1セッションの終点
H4    休止（ユーザーが読書・調査し、結果を持ち帰る）
H5    更新（証拠エントリを台帳に記入 → 確信度更新 → 仮説の淘汰・分岐・追加）
      → H2 へ戻る／収束宣言／判別不能宣言（層を明示して deliberation-sim 等へ）
```

会話をまたぐ探究なので、状態はすべて台帳（LEDGER.md）に外部化する。再開セッションは台帳だけ読めば文脈が復元できること。詳細手順と台帳テンプレートは `PROTOCOL.md`。

## 三層判別（どこで決着するかを最初に宣言する）

| 層 | 決着のつき方 | 典型領域 |
|---|---|---|
| 文献判別 | 実証データ・一次資料の確認で決まる | 薬理の効果論争・歴史事実・実証研究の再現性 |
| 概念判別 | 思考実験・整合性テスト・立証責任の所在で決まる | クオリア・自由意志・法解釈の体系適合性 |
| 機序判別 | 提案された機構がどこまで観測を予測できるかで決まる | 作用機序・因果メカニズムの妥当性 |

裁定者は H3 の前に「この問いはどの層で決着しうるか（あるいはしないか）」を宣言する。詳細は `reference/discrimination-modes.md`。

## 絶対禁則

1. **相互排他性のない仮説群は競争に進めない。** 全部同時に正しくありうる仮説の束は「観点の一覧」であって競争にならない。少なくとも一つの観測・文献確認で予測が食い違うよう再設計する。
2. **自滅条件を宣言していない仮説は立論に進めない。** 反証不能な仮説はその旨を明示し、概念判別層へ回すか除外する。
3. **steelman の承認なき攻撃は無効**（deliberation-sim と同じ）。相手の最強版を再構成し、承認を得てから撃つ。
4. **台帳に証拠エントリのない確信度変更は差し戻す。** 更新には必ず「何を読んだ／確認した結果か」を紐づける。
5. **機序の物語で証拠階層を飛ばさない。** もっともらしいメカニズム説明は仮説の資格であって証拠の代替ではない（→ `reference/evidence-grading.md`）。
6. **未読文献の内容を捏造しない。** 文献予測は必ず `【未読・予測】` タグをつけ、確認後に `【確認済】` へ更新する。検索で実在を確認できない文献を引かない。
7. **判別不能を「引き分け」で誤魔化さない。** 判別不能ならその理由の型（過小決定・価値問題・言語的論争）を宣言して出口を示す。
8. **医療・投資・個別法律相談への断定に踏み込まない。** 論争の構造と証拠の現状を示すまでで止める。

## 出力物

- 仮説カード一覧（H0 時点でユーザー承認を取る）
- 確信度台帳つき LEDGER.md（`templates/LEDGER.md` の書式。渡し方は「環境固有の設定」に従う）
- **判別読書リスト**（期待情報量順。各項目に「どの仮説がどう傷つくか」を明記）
- 収束時：決着サマリ（生き残った仮説・淘汰の経緯・残る不確実性）
- 判別不能時：不能の型の宣言と出口（deliberation-sim への送付状 等）

## 環境固有の設定

既定はこの表のとおり。同じディレクトリに `local.md` があれば、その記載で上書きする（無ければ何もしない）。

| 項目 | 既定（どの環境でも動く） | local.md で上書きできること |
|---|---|---|
| 台帳・報告の保存 | ダウンロード可能な Markdown ファイルとして返す。filesystem が使える環境で保存先を指定されればそこに書く | 保存先のパス |
| 立論の独立性 | 1つの会話で順に書く（台帳に「非独立立論」と記す） | サブエージェント並列（Claude Code の Agent ツール）の有効化 |
| 継続運用の観測点 | 本文に期日と判定手順を書いて人間に渡す | 期日管理ツール（thread 等）への書き出し |
| 先行調査の情報源 | Web 検索と会話内の情報 | 既存の知識ベース（wiki 等）を先に当てる |

`local.md.example` に上書きの書き方の例がある。claude.ai だけで使う場合は無視してよい。
