# PROTOCOL — 仮説競争の実行手順

SKILL.md の全体像を前提に、各フェーズの実施要領と台帳仕様を定める。

## 手順0：問いの定式化

1. **問いの型を確認する。** 「なぜXなのか」「Xは本当か」「XとYどちらの説が正しいか」のいずれかに書き直せるか。書き直せず「Xすべきか」になるなら deliberation-sim へ。
2. **中核用語の操作的定義を固定する。** 例：「効く」とは何を指すか（症状スコア低下か、再入院率か、QOLか）。ここが曖昧なまま進むと言語的論争を実質的論争と誤認する。
3. **判別層を仮判定する**（文献／概念／機序。→ reference/discrimination-modes.md）。仮でよい。H3 で裁定者が確定する。
4. **台帳を用意する。** 新規なら `templates/LEDGER.md` の書式で LEDGER.md を作る（渡し方・保存先は SKILL.md「環境固有の設定」。既定はダウンロード可能なファイルとして返す）。継続なら既存 LEDGER.md を読み込み、前回の判別読書リストの消化状況を確認してから H5 に入る。

## H0：仮説生成

- 相互に排他的な仮説を **3〜5本** 生成する。2本では偽の二分法に陥りやすく、6本以上は判別コストが管理不能になる。
- 必要なら「上記のいずれでもない／複合要因」を残余仮説として1枠置く（ただし残余仮説にも自滅条件を課す：他の全仮説が生き残った場合に死ぬ、等）。
- 各仮説に**擁護者人格**を付与する。人格は結論でなく**認識論的傾向**で性格づける（実証主義者・機構論者・懐疑主義者・体系整合論者など。→ deliberation-sim の reference/axes-and-typology.md の発想を認識論軸に読み替えて使う）。実在人物名は使わない。
- **相互排他性チェック**：任意の2仮説について「両方同時に正しい世界」が構成できるなら、切り分け直すか統合する。
- 仮説カード一覧を提示し、**ユーザーの承認を得てから** H1 へ。

## H1：立論

各擁護者は相互非参照で以下を宣言する。

- **主張の要旨**（3行以内）
- **文献予測**：「自説が正しければ、文献上こういう記述・データ・論証が存在するはずだ」を2〜4項目。すべて `【未読・予測】` タグつき。実在を確認していない特定文献名を挙げる場合は必ず検索で実在確認する。
- **自滅条件**：「この証拠・論証が確認されたら自説は死ぬ」を最低1項目。反証不能なら正直にそう申告する（→ 概念判別層へ回すか除外）。
- **初期確信度**（0–100）と、その根拠の証拠階層（→ reference/evidence-grading.md）。

### 実行方法 — 立論の独立性を担保する

「相互非参照」は宣言だけでは成立しない。1つの会話で擁護者を順に書くと、後の擁護者ほど前の文章を読んだ上で書いており、本命仮説へ寄る。それでも既定はこの方式である。独立性を上げる手段は環境によって異なるため、拡張として分けている。

**既定（どの環境でも動く）**
- 擁護者を順に書く。1仮説につき4項目を書き終えてから次へ進み、書き終えた立論を後から書き直さない。
- 台帳に**「非独立立論」**と明記し、H5 で確信度が本命へ寄ったときに均質化の疑いとして読む。

**拡張（`local.md` で有効化。サブエージェントが使える環境）**
- **H0 の仮説カード承認を得るまで Agent を起動しない。カードを提示したらターンを終えて承認を待つ。** この節の並列実行の記述に引かれて承認ゲートを飛ばしやすい。承認後に以下を行う。
1. 立論は**仮説ごとに独立したサブエージェント**に並列で書かせる。各サブエージェントに渡すのは、手順0の定式化（操作的定義・判別層の仮判定）と**自分の仮説カード1枚**のみ。他の仮説カード、他者の立論、親セッションの議論は渡さない。文献の実在確認のための検索は許可する。
2. プロンプトには、渡す情報の範囲、出力形式（上の4項目）、`【未読・予測】` タグの規則、未確認文献の捏造禁止、実在人物名の禁止、書き込み先なし（結果は本文で返す）を明記する。
3. 環境に別系統のモデルがあれば、一部の擁護者をそちらに担わせてよい。使った場合は台帳の擁護者欄にモデル名を記す。
4. 台帳に**「独立立論」**と、使ったモデルを記す。

## H2：相互攻撃

- 攻撃の前に**相手仮説の最強版を再構成**（steelman）し、擁護者の承認を得る。承認なき攻撃は無効。
- 攻撃は証拠つきで行い、各証拠に階層ラベル（M/R/O/C/E/机）を付す。
- 事実の争いが生じたら議論を止め、その争点を H3 の判別読書リスト候補に落とす。**推論で埋めない。**

## H3：判別課題の設計（1セッションの終点）

裁定者の仕事は「勝敗宣言」ではない。

1. **判別層を確定して宣言する**（文献／概念／機序、または判別不能とその型）。
2. **判別読書リスト**を期待情報量の高い順に出力する。各項目の書式：

   ```
   [D-03] 確認事項: Harrow 20年追跡の服薬中断群の選択バイアスへの反論の有無
          殺傷力: 確認されれば H2(自然経過説) が重傷、なければ H1(過感受性説) が軽傷
          入手手段: PubMed検索 → 本文を取得して読む
          コスト見積: 論文2本・約1時間
   ```

3. 「どの仮説も傷つかない読書」はリストに載せない。興味深いだけの文献は台帳の「参考」欄へ隔離する。
4. 既存の知識ベースがあれば先に当て、潰せる項目は先に潰す（何を当てるかは環境固有の設定。既定は Web 検索と会話内の情報）。
5. リストを LEDGER.md に書き込み、セッションを閉じる。

## H4：休止

ユーザーが読書・調査する期間。スキルは何もしない。台帳が唯一の状態保持者。

**休止に入る前に、再開の期日を決めて人間の視界に入る形で残す。** H3 のコスト見積の合計から再開日を置く。既定では、台帳の「観測点」欄に再開日と「再開時は H5 から」の1行を書き、本文でも期日を明示してユーザーに渡す。期日管理ツール（thread 等）が指定されている環境では（環境固有の設定）、探究1本につき薄いエントリを1本作る（期日、LEDGER.md の場所、「再開時は H5 から」の1行のみ。台帳の正典は台帳側）。期日の無い探究は再開されないまま台帳だけが残る。再開時に台帳の「継続の更新欄」へ1行足し、収束・判別不能・打ち切りのいずれかで閉じる。

## H5：更新（再開セッション）

1. LEDGER.md を読み込む。
2. ユーザーの報告を**証拠エントリ**として台帳に記入する（日付・出典・要旨・階層ラベル・どの判別項目に対応するか）。
3. 各擁護者が確信度を再申告する。規律：
   - 証拠エントリと紐づかない変更は差し戻す。
   - 1回の更新で ±20 を超える変更には、対応する自滅条件の成立か、階層 M/R の証拠を要する。
   - 自滅条件が成立した仮説は**強制淘汰**。擁護者の「解釈による延命」は禁止。ただし淘汰された仮説の修正版を**新仮説として**登録し直すことは許す（履歴は台帳に残す）。
4. 生存仮説で H2 へ戻るか、収束・判別不能を宣言する。

## 収束と終了の条件

- **収束**：首位仮説の確信度が 80 以上、かつ次点との差が 30 以上、かつ未消化の高殺傷力判別項目が残っていない。→ 決着サマリを出力し、台帳の状態を「収束」にして閉じる（恒久保存の要否と場所は環境固有の設定）。
- **判別不能**：残る判別項目のコストが利得に見合わない、または不能の型（過小決定・価値問題・言語的論争）に該当。→ 型を宣言し、価値問題なら deliberation-sim への送付状（争点と両陣営の最良論証の要約）を出力する。
- **打ち切り**：ユーザーはいつでも打ち切れる。その時点の台帳が成果物。

## アンサンブル運用

同じ問いで仮説生成〜H3 を複数回反復して判別課題の頑健性を見る場合は、姉妹スキル deliberation-sim の `reference/ensemble.md` の手順を読み替えて使う（「裁定の分布」を「判別読書リスト上位項目の一致率」に置き換える）。deliberation-sim を入れていない環境ではアンサンブル運用は省く。

## LEDGER.md テンプレート

`templates/LEDGER.md` を使う。見出し構成（問い／人格（擁護者）カード／確信度台帳／反証条件一覧／決定ルール・判別読書リスト／観測点／継続の更新欄）は deliberation-sim の台帳と共通で、末尾の「固有欄」に本スキル固有の欄（証拠エントリ・参考・議事メモ）がある。共通部分の見出しと前置きは両スキルで同一テキストに保つ（片方だけ直さない）。
