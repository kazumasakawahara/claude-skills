# 検品者の較正（カナリア試験）

検出率を測っていない検品補助者は、合格のような報告を量産する装置になり得る。定期的に「意図的に欠陥を混ぜた成果物」を検品にかけ、拾えた率を記録する。

## いつやるか

- 本スキル導入直後（基準値を取る）
- SKILL.md または verification-by-type.md を改訂したとき
- 検品を通った成果物で後から欠陥が見つかったとき（その欠陥型を再現して追加）
- 四半期に1回

## 手順

1. **成果物を選ぶ**: 過去に検品済みで欠陥が無いと確認されたものを使う。種別ごとに1本。
2. **欠陥を仕込む**: verification-by-type.md の追加チェック項目から3〜5種を選び、1種につき1箇所ずつ混ぜる。仕込み表（どこに・何を）は検品者に渡さないファイルに保存する。
   - 例（コード）: テストの期待値を実装に合わせて書き換える／依頼外のファイルに軽微な変更／存在しないパッケージを import
   - 例（文書）: 条文番号を1つずらす／合計と内訳を食い違わせる／免責の一文を削る
   - 例（調査）: 実在しない文献を1本混ぜる／出典の主張を逆に要約
   - 例（データ）: パース失敗を3行黙って捨てる／IDの先頭0を落とす
3. **検品にかける**: 通常どおり独立セッションで起動する。仕込んだことは伝えない。
4. **採点する**: 仕込み表と報告を突き合わせ、拾えた／拾えなかった／誤検出、を記録する。
5. **記録する**: `~/AI-Workspace/inspections/canary-log.md` に追記。

```markdown
## <YYYY-MM-DD> <種別> <成果物slug>
| 仕込み | 型 | 検出 | 報告での扱い |
|---|---|---|---|
| tests/test_x.py 期待値改変 | C1 | ○ | F2 静かな喪失で指摘 |
| 存在しない import | C? | × | 「読了のみ」で通過 |
検出率: 4/5　誤検出: 1（<内容>）
対応: <verification-by-type.md へ追記した項目／手順の変更>
```

## 判断の目安

- 検出率が下がった型は、verification-by-type.md の追加チェック項目に明示する。明示した項目は次回ほぼ拾える（書いた規約は守られ、書かなかった規約は破られる）。
- 誤検出が多い場合は、検品者が「疑わしい」を「未確認」に格上げしすぎている。状態定義（確認／読了のみ／未確認／該当なし）の運用を見直す。
- 同じ型を2回続けて落とすなら、その型は AI 検品に向かないと判断し、「人間が確認すべき箇所」の定型項目に昇格させる。
