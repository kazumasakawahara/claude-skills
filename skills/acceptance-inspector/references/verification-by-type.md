# 種別別の独立検証手段と固定チェック項目

SKILL.md 手順2で参照する。各種別について「独立手段」（作業者の主張に依存せず事実を観測する方法）と、その種別で頻出する欠陥に対応した追加チェック項目を挙げる。
複数種別にまたがる成果物（例: 調査に基づくコード変更）は該当する節をすべて当てる。

canary.md で拾えなかった欠陥の型は、該当する節の追加項目へ追記すること。

---

## 1. コード（実装・修正・リファクタ・移行）

### 独立手段
- **差分全体を取る**: `git diff <base>..<head> --stat` で変更ファイル一覧、続いて全ファイルの差分本体。作業者の「変更しました」リストと突き合わせる。
- **自分でテストを実行する**: 作業者の「テスト通りました」は主張。同じコマンドを自分で叩き、出力を報告に貼る（token-lean-tool-output で量を制御）。
- **テストの中身を見る**: テストが通っても、テストが緩められた・スキップされた・削除された・期待値が実装に合わせて書き換えられた、を見る。`git diff` でテストファイルの変更を別扱いで読む。
- **型検査・lint・ビルド**を実行する。作業者が「警告のみ」と言っている場合は警告の中身を読む。
- **依存の実在**: 新規追加された import・パッケージ・バージョンが実在し、ロックファイルと一致するか。Context7 で API の実在を確認する。
- **手動で1本通す**: 可能なら主要経路を1回実際に動かす（起動・リクエスト・CLI実行）。テストが通っていてもエントリポイントが壊れている例は多い。

### 追加チェック項目
| # | 項目 | 典型的な欠陥 |
|---|---|---|
| C1 | テストの改変 | 期待値の書き換え、skip/xfail の追加、テストの削除 |
| C2 | エラー処理の握り潰し | `except: pass`、広い catch、失敗を成功として返す |
| C3 | ハードコード | 秘密情報・環境固有パス・ダミー値の残置 |
| C4 | 依頼外のリファクタ | 「ついでに」整理された無関係ファイル |
| C5 | 移行の片道 | マイグレーションに down が無い、旧データの扱いが未定義 |
| C6 | 境界値 | 空・0件・null・最大長・同時実行での挙動が未検証 |
| C7 | 設定・環境変数 | 新しい環境変数が .env.example・README に反映されていない |
| C8 | PII・機密 | ログ・テストフィクスチャ・コメントに実データ |

## 2. 文書・原稿（記事・手順書・報告書・契約書案・申請書類）

### 独立手段
- **受入基準の逐条照合**: 「含めるべき要素」を一つずつ本文中に位置特定する。無い要素は「無い」と書く（「概ね網羅」は禁止）。
- **事実・数値の原典照合**: 本文中の数値・日付・固有名詞・条文番号を原典に当たる（legal-research、web_fetch、資料の該当ページ）。出典が示されていない事実は「出典不明」として列挙する。
- **旧版との差分**: 改訂の場合、`diff` を取り、消えた段落・変わった数値を列挙する。
- **読者要件の確認**: 想定読者（利用者・家族・行政・裁判所）に対する語彙・敬体・分量が基準に合うか。基準に無ければ「読者要件の定義なし」と報告。
- **形式要件の機械確認**: 文字数・ページ数・見出し構成・書式（フォント・余白・提出フォーマット）を数える。目視で「だいたい」を言わない。

### 追加チェック項目
| # | 項目 | 典型的な欠陥 |
|---|---|---|
| D1 | 出典の実在 | 実在しない判例・文献・URL、実在するが内容が違う |
| D2 | 数値の整合 | 本文と表、合計と内訳、前後の段落で数値が食い違う |
| D3 | 断定の根拠 | 「一般に」「通常は」で根拠なく断定 |
| D4 | 法令・制度の時点 | 改正前の条文・廃止された制度・古い金額 |
| D5 | 固有名詞の正確さ | 機関名・人名・住所・制度名の誤記 |
| D6 | 削られた注意書き | 免責・例外・要確認事項が改訂で消えている |
| D7 | PII | 実名・生年月日・障害情報が匿名化されずに残る |
| D8 | 指示の反転 | 「〜しないこと」が「〜すること」で書かれている |

## 3. 調査・分析（リサーチレポート・比較・要約・仮説検証）

### 独立手段
- **出典の全数実在確認**: 参照された文献・URL・データセットをすべて開く。サンプリングしない。
- **引用の忠実性**: 出典が実在しても、要約が出典の主張と一致するかを該当箇所で確認する。反対のことを言っている例、限定条件が落ちている例が多い。
- **数値の再計算**: 集計・比率・増減率を元データから自分で計算する。
- **検索の再現**: 「〜は見つからなかった」「〜が最新」という主張は、自分でも検索して確認する。
- **反証の探索**: 結論と逆の結論を支持する情報源を1回は探す。見つかれば「未考慮の反証あり」として報告する（結論の当否は判定しない）。

### 追加チェック項目
| # | 項目 | 典型的な欠陥 |
|---|---|---|
| R1 | 捏造出典 | もっともらしい著者・年・誌名の組み合わせ |
| R2 | 過剰一般化 | 1事例・1地域の結果を全体の結論にしている |
| R3 | 時点の混同 | 古い数値を現在の数値として扱う |
| R4 | 二次情報の一次化 | 要約サイト・SNSを一次資料として扱う |
| R5 | 質問への非対応 | 問われたことと別のことに答えている（F3の調査版） |
| R6 | 確信度の不表示 | 推測と確認済み事実が同じ文体で並ぶ |
| R7 | 「見つからない」の未検証 | 探索の記録がなく不在を断定 |

## 4. データ処理（変換・集計・クレンジング・移行・スクレイピング）

### 独立手段
- **件数照合**: 入力件数・出力件数・除外件数の三者を数え、`入力 = 出力 + 除外` が成立するか確認する。差があれば「行方不明の件数」として報告。
- **サンプル逆引き**: 出力の数行を入力に戻して突き合わせる。先頭だけでなく末尾・中間・特殊文字を含む行を選ぶ。
- **集計の再計算**: 合計・平均・区分ごとの件数を別手段（pandas／SQL／手計算）で出し直す。
- **スキーマ照合**: 列名・型・必須列・キーの一意性を実データに対して確認する。
- **冪等性**: 同じ処理を2回走らせて結果が同じか（重複挿入・二重計上がないか）。
- **エンコーディング・ロケール**: 日本語・全角半角・日付書式・小数点区切りが壊れていないか、実データで見る。

### 追加チェック項目
| # | 項目 | 典型的な欠陥 |
|---|---|---|
| T1 | 静かなドロップ | パース失敗行が警告なく捨てられる |
| T2 | 型の暗黙変換 | 郵便番号・ID の先頭0落ち、日付が数値化 |
| T3 | 重複 | キー重複・二重取り込み |
| T4 | 境界の取り違え | 以上／超、期間の端の日 |
| T5 | 結合の膨張・欠落 | JOIN で件数が増減 |
| T6 | 元データの上書き | 入力ファイルがその場で書き換えられている |
| T7 | PII の流出先 | 出力・ログ・中間ファイルに実データ |

## 5. 設定・運用変更（MCP設定・hooks・cron・権限・インフラ・環境変数）

### 独立手段
- **適用前後の差分**: 設定ファイルの diff。バックアップの実在（パス・タイムスタンプ）を確認する。
- **実際に動かす**: 設定が「読まれている」ことを確認する（新規セッション起動・ログにエントリが出る・`status` コマンド）。既存セッションには反映されないものが多い点に注意（CLAUDE.md、環境変数）。
- **復元手順の実行可能性**: 「戻せます」の主張に対し、復元コマンドが実際に存在し、対象ファイルが残っているかを見る。
- **副作用の範囲**: 変更が他プロジェクト・他ツールに波及するか（グローバル設定・共有認証・PATH）。
- **権限**: chmod・所有者・公開範囲が意図どおりか。秘密情報がプレーンテキストで増えていないか。

### 追加チェック項目
| # | 項目 | 典型的な欠陥 |
|---|---|---|
| O1 | バックアップ不在 | 「バックアップしました」に実体がない |
| O2 | 反映未確認 | 書き換えたが読み込まれていない |
| O3 | 横断汚染 | 固有の文言や指示が全プロジェクトに混入 |
| O4 | 死んだ設定 | 参照先ツールが存在しないマッチャ・フック |
| O5 | 秘密情報 | 設定ファイルへの直書き |
| O6 | 復元不能 | 戻し手順が未検証 |
| O7 | 観測手段の喪失 | deny・権限縮小後に、作業者の記載値（サイズ・行数・日時）を誰も照合できない。作業前の観測値が ACCEPTANCE.md に固定されていない（2026-09-08 実走で検出） |
| O8 | 計測値の注記漏れ | `wc -l` が末尾改行なしの1行ファイルで 0 を返すなど、手段の癖が記載値に無注記で反映（同上） |

## 手段が使えないときの書き方

手段が無い項目は必ず「未確認（手段なし: <理由>）」と書き、「人間が確認すべき箇所」に、その手段を人間がどう確保できるかを添える（例: 「実行環境がないため、河原さんの Mac で `pytest -q` を1回回してください」）。
