# genogram（家族関係の図）

ある人物を中心に、その家族の関係を 1 枚の図にする。図はスクリプトが描く。Claude の仕事は、家族の構成を人ごとの記録（persons.json）に写すことと、図に描けなかったことを伝えること。

## 絶対に守ること

同じフォルダに `local.md` があれば、先に読んで従う（その環境だけの決まり）。

**入力は 3 つ**

1. 使う人が会話で伝える家族の構成
2. 確定した家族の一覧（persons.json の形のファイル）
3. 仮名（イニシャル）になっていると使う人が伝えた資料

**資料を示されたとき**

- **開く前に確かめる。** 使う人が「仮名（イニシャル）になっている」と伝えているかを見る。伝えていれば開く。
- 伝えていなければ、資料を開かない（Read・cat・grep などで中身を見ない。添付された資料も読み取りの元にしない）。次のとおり尋ねて止まる：「この資料は、名前が仮名（イニシャル）になっていますか。なっていれば、開いて家族の図を作り直します。実名が入っている場合は、家族の構成を仮名で伝えてください。」
- 開いた資料に、実名らしい名前・住所・電話番号が見つかったら、読み進めずに止まって知らせる。記録にも図にも写さない。
- **相談資料を点検してから扱う別のスキルや手順が入っている環境では、その手順の対象の資料はそちらに譲る。** このスキルで代わりに読まない。

**名前**

- **実在の人の名前を入れない。** 図に出る名前（name）は、仮名・イニシャル・続柄にする。資料がイニシャルなら、そのまま使う。
- 実名らしい名前で伝えられたら、記録に写さず、図に入れる仮名を尋ねる。

**書かれていないことを補わない**

- 続柄・性別・生死・親子・夫婦の関係は、伝えられたこと・資料にあることだけを書く。分からない欄は書かない（空欄のまま）。名前や年齢から性別を決めない。子の人数や年金の話から、人の存在を決めない。
- **線を勝手に引かない。** 「A の子」とあるだけなら、親は A だけにする。もう一方の親を推し量って足さない。図の注記に「もう一方の親は資料に記載なし（戸籍で確かめる）」と出る。これは誤りではなく、確かめる点の一覧である。
- 年齢を計算しない。生年月だけが分かる人は、年齢の欄を空欄にする（記号の中に数字は出ない）。
- **図の読みを足さない。** 家族の評価・診断・支援の方針は、図にも注記にも書かない。

## 描ける範囲

- 中心の人と、その親・きょうだい・配偶者（離婚・事実婚・その解消・婚姻外の親どうしを含む）・子・孫。
- **描くのは一方の家系と、婚姻や事実婚で入った人。** 夫婦の両方の親（双方の実家）を 1 枚に描くことはできない。両方に親の記録があると、検査が警告を出す。どちらの家系を描くかを尋ねる。
- 1 人の相手（結婚・事実婚の相手）は、3 人まで描ける（例：離婚 2 回と、今の内縁の相手）。3 人目の線は、記号の下を回して描く。4 人以上いるときと、相手が 3 人いて子もいるときは、線が重なって読みにくくなり、検査が警告を出す。
- 養親と実親を同じ図に描くことはできない（親は 2 人まで）。

## 手順

### 1. 聞く・読む

**会話で伝えられたとき：** 伝えられた内容から、人と関係を拾う。足りない点を一度に全部尋ねない。先に確かめるのは、**中心の人は誰か**と、**どの範囲まで描くか**の 2 点だけ。あとは分かる範囲で描き、注記で不足を示す。「○○さんを中心に」と頼まれていれば、中心の人は尋ねない。

**確定した家族の一覧（persons.json の形）を渡されたとき：** この節と次の節を飛ばして「3. 検査して描く」に進む。中身を書き換えない。

**仮名になっている資料から作り直すとき：**

1. 家族の図は、図形で描かれていることが多い。文字の取り出しだけで済ませない。ページを画像にして、家族の図を目で見る（Word の文書は PDF に変換してから画像にする）。
2. 写すのは家族の構成だけにする。病名・収入・相談の中身は、記録にも図にも写さない。
3. 図の記号と線の読み方は、その資料の描き方に従う（□＝男性、○＝女性、二重の記号＝中心の人、斜線＝離婚、×や黒塗り＝死亡、など）。読み方に迷う記号は、決めずに尋ねる。
4. 元号の年は西暦に直す。月が分からない離婚は、年だけを書く。

### 2. persons.json を書く

```json
{"persons": [
  {"id": "ichiro", "name": "一郎", "relation": "本人", "center": true, "sex": "male", "age": 45,
   "cohabiting": true, "alive": true,
   "parents": ["shigeru", "kazuko"],
   "partners": [{"person": "yoko", "status": "divorced", "divorced": "2019-03"}]}
]}
```

| 欄 | 書き方 |
|---|---|
| `id` | 英小文字の記号。人ごとに別のもの（必須） |
| `name` | 図に出る名前。仮名・イニシャル・続柄 |
| `relation` | 続柄。伝えられた言葉のまま（「本人」「母」「長女」） |
| `center` | 中心の人に `true`（1 人だけ）。記号が二重の枠になる。「○○さんを中心に」と頼まれたら、その人に付ける |
| `sex` | `male`／`female`。伝えられているか、性別の分かる続柄（長男・妻・母など）か、資料の図の記号で分かるときだけ。それ以外は書かない（◇で描かれる） |
| `age` | 整数。伝えられた数字のまま。計算しない |
| `cohabiting` | 中心の人と同居なら `true`、別居なら `false`。同居かどうかは、中心の人から見て書く |
| `alive` | 存命なら `true`、死亡なら `false`（記号が黒く塗られる） |
| `parents` | 親の `id` の並び。2 人まで |
| `partners` | 相手ごとに `person`（相手の `id`）と `status`。相手の側にも同じ `status` で書く |
| `placeholder` | 名前も属性も分からないが、関係だけ分かる人は `true`（破線の記号と「情報なし」）。例：「離婚した」とだけある相手 |

`status` は次の 6 つ。

| status | 意味 | 線 | 年月の欄 |
|---|---|---|---|
| `married` | 婚姻 | 二重線 | なし |
| `divorced` | 離婚 | 二重線に // | `divorced`（西暦。YYYY-MM か、年だけの YYYY。分かるときだけ） |
| `de_facto` | 事実婚・内縁 | 破線 | なし |
| `de_facto_ended` | 事実婚・内縁の解消 | 破線に // | `ended`（西暦。YYYY-MM か、年だけの YYYY。分かるときだけ） |
| `non_marital` | 婚姻も事実婚もない親どうし | 点線と「婚姻外」 | なし |
| `couple` | 夫婦・両親（婚姻かどうかは伝えられていない） | 一本線 | なし |

- 「両親」「夫婦」とだけ伝えられ、婚姻しているかどうかが分からないときは `couple` にする。`married` にしない（婚姻と決めない）。
- 「結婚している」「妻」「夫」「婚姻」と伝えられたら `married`。
- 2 人が親であることだけが分かり、2 人の関係が何も伝えられていないときは、`partners` を書かない。図では 2 人を並べ、2 人から子へ線を下ろす（2 人の間に線は引かない）。注記に「関係は資料に記載なし」と出る。

推し量って書いた点があるとき（同居かどうか、など）は、値を `{"value": true, "inferred": "理由を一文で"}` の形にする。注記に「推認」と理由が出る。**続柄・性別・生死と、親子・夫婦の線には、この形を使えない**（検査が誤りにする）。

全部の欄を使った見本は `examples/persons.example.json` にある（架空の世帯）。

### 3. 検査して描く

このスキルのフォルダで実行する。

```
python3 scripts/draw.py persons.json -o genogram.svg
```

- 誤りが出たら、図は書かれない。表示された誤りを persons.json で直して、もう一度実行する。誤りを消すために、分かっていない値を足さない。
- 警告 `both_sides_parents`・`many_partners`・`partners_children` が出たら、「描ける範囲」のとおり伝える。
- 亡くなった人の記号は、黒く塗って描く（既定）。「死亡は×で」と頼まれたときは、`--dead cross` を付けて描く。
- 標準ライブラリだけで動く（Python 3.9 以上）。追加の導入は要らない。

### 4. 渡す

1. 渡す前に、図を画像にして自分で見る。線が記号や字に重なっていないか、伝えられた関係（婚姻・離婚の回数など）が全部出ているかを確かめる。出ていない点があれば、直すか、そのことを伝える。
1. 図を渡す。チャットで図を見せるときは PNG も作る（下の「PNG にするとき」）。
2. スクリプトが表示した「図の下に添える注記」を、そのまま図の下に書く。言い換えない。
3. 資料から作り直したときは、**図から読んだ点**と**本文から読んだ点**を分けて伝え、確かめてもらう（例：「父母の婚姻は、図の線から読みました」）。

**PNG にするとき：** 図の文字は Mac のフォント（Hiragino Sans）を指定している。そのフォントが無い環境では、文字の幅がずれるか、文字が出ない。その環境にある日本語のフォントの名前を調べて（`fc-list :lang=ja`）、`--font` で指定して描き直してから変換する。

```
python3 scripts/draw.py persons.json -o genogram.svg --font "Noto Sans CJK JP"
rsvg-convert -z 1.4 genogram.svg -o genogram.png
```

日本語のフォントが 1 つも無ければ、SVG のまま渡してその旨を伝える。

## 直しの依頼を受けたとき

図の見た目を手で直さない。persons.json を直して描き直す。同じ記録からは同じ図が出るので、記録が図の原本になる。

## 個人の情報を扱うとき

家族関係は、それだけで人を特定できることがある。仮名にした図でも、渡す相手と保管の場所は使う人が決める。Claude からは、図を外に送る操作をしない。

## 環境固有の設定

既定では設定は要らない。相談資料を扱う別のスキルや手順がある環境では、譲る相手と場所を `local.md` に書く（書き方は `local.md.example`）。`local.md` は配布物に入らない。

## 関連スキル

単体で動く。ほかのスキルは要らない。支援機関とのつながりの図や、相続関係の図は、このスキルの対象ではない。
