# genogram（家族関係の図）

ある人物を中心に、その家族の関係を 1 枚の図にする。図はスクリプトが描く。Claude の仕事は、伝えられた家族の構成を人ごとの記録（persons.json）に写すことと、図に描けなかったことを伝えること。

## 絶対に守ること

同じフォルダに `local.md` があれば、先に読んで従う（その環境だけの決まり）。

**始め方**

- **相談票・相談資料そのものからは始めない。** このスキルは資料を読む道具ではない。資料のファイルを開かない（Read・cat・grep などで中身を見ない）。会話に添付された資料も、読み取りの元にしない。
- 資料から図を頼まれたら（「この相談票の家族関係を図にして」など）、読み進めずに次のとおり案内して止まる：「このスキルは資料を読みません。家族の構成を仮名で伝えてください（続柄・年齢や生年月・同居・婚姻や離婚など）。確定した家族の一覧（persons.json の形）があれば、それを渡してください。」
- **相談資料を点検してから扱う別のスキルや手順が入っている環境では、相談票・相談資料からの依頼はそちらに譲る。** このスキルで代わりに読まない。
- 入力は 2 つだけ：使う人が伝える家族の構成と、確定した家族の一覧（persons.json の形のファイル）。後者は、開いて検査と描画にかけてよい。

**名前**

- **実在の人の名前を入れない。** 図に出る名前（name）は、仮名・続柄・イニシャルにする。仮名で伝えてもらう。
- 実名らしい名前で伝えられたら、記録に写さず、図に入れる仮名を尋ねる。

**書かれていないことを補わない**

- 続柄・性別・生死・親子・夫婦の関係は、伝えられたことだけを書く。分からない欄は書かない（空欄のまま）。名前や年齢から性別を決めない。子の人数や年金の話から、人の存在を決めない。
- **線を勝手に引かない。** 「A の子」と伝えられただけなら、親は A だけにする。もう一方の親を推し量って足さない。図の注記に「もう一方の親は資料に記載なし（戸籍で確かめる）」と出る。これは誤りではなく、確かめる点の一覧である。
- 年齢を計算しない。生年月だけが伝えられた人は、年齢の欄を空欄にする（記号の中に数字は出ない）。
- **図の読みを足さない。** 家族の評価・診断・支援の方針は、図にも注記にも書かない。

## 描ける範囲

- 中心の人と、その親・きょうだい・配偶者（離婚・事実婚・その解消・婚姻外の親どうしを含む）・子・孫。
- **描くのは一方の家系と、婚姻や事実婚で入った人。** 夫婦の両方の親（双方の実家）を 1 枚に描くことはできない。両方に親の記録があると、検査が警告を出す。どちらの家系を描くかを依頼者に尋ねる。
- 養親と実親を同じ図に描くことはできない（親は 2 人まで）。

## 手順

### 1. 聞く

伝えられた内容から、人と関係を拾う。足りない点を一度に全部尋ねない。先に確かめるのは、**中心の人は誰か**と、**どの範囲まで描くか**の 2 点だけ。あとは分かる範囲で描き、注記で不足を示す。

確定した家族の一覧（persons.json の形）を渡されたときは、この節と次の節を飛ばして「3. 検査して描く」に進む。中身を書き換えない。

### 2. persons.json を書く

```json
{"persons": [
  {"id": "ichiro", "name": "一郎", "relation": "本人", "sex": "male", "age": 45,
   "cohabiting": true, "alive": true,
   "parents": ["shigeru", "kazuko"],
   "partners": [{"person": "yoko", "status": "divorced", "divorced": "2019-03"}]}
]}
```

| 欄 | 書き方 |
|---|---|
| `id` | 英小文字の記号。人ごとに別のもの（必須） |
| `name` | 図に出る名前。仮名・続柄・イニシャル |
| `relation` | 続柄。伝えられた言葉のまま（「本人」「母」「長女」） |
| `sex` | `male`／`female`。伝えられているか、性別の分かる続柄（長男・妻・母など）のときだけ。それ以外は書かない（◇で描かれる） |
| `age` | 整数。伝えられた数字のまま。計算しない |
| `cohabiting` | 中心の人と同居なら `true`、別居なら `false` |
| `alive` | 存命なら `true`、死亡なら `false`（×が付く） |
| `parents` | 親の `id` の並び。2 人まで |
| `partners` | 相手ごとに `person`（相手の `id`）と `status`。相手の側にも同じ `status` で書く |
| `placeholder` | 名前も属性も分からないが、関係だけ伝えられた人は `true`（破線の記号と「情報なし」）。例：「離婚した」とだけ伝えられた相手 |

`status` は次の 5 つ。

| status | 意味 | 線 | 年月の欄 |
|---|---|---|---|
| `married` | 婚姻 | 二重線 | なし |
| `divorced` | 離婚 | 二重線に // | `divorced`（YYYY-MM。分かるときだけ） |
| `de_facto` | 事実婚・内縁 | 破線 | なし |
| `de_facto_ended` | 事実婚・内縁の解消 | 破線に // | `ended`（YYYY-MM。分かるときだけ） |
| `non_marital` | 婚姻も事実婚もない親どうし | 点線と「婚姻外」 | なし |

推し量って書いた点があるとき（同居かどうか、など）は、値を `{"value": true, "inferred": "理由を一文で"}` の形にする。注記に「推認」と理由が出る。**続柄・性別・生死と、親子・夫婦の線には、この形を使えない**（検査が誤りにする）。

全部の欄を使った見本は `examples/persons.example.json` にある（架空の世帯）。

### 3. 検査して描く

このスキルのフォルダで実行する。

```
python3 scripts/draw.py persons.json -o genogram.svg
```

- 誤りが出たら、図は書かれない。表示された誤りを persons.json で直して、もう一度実行する。誤りを消すために、伝えられていない値を足さない。
- 警告 `both_sides_parents` が出たら、「描ける範囲」のとおり依頼者に尋ねる。
- 標準ライブラリだけで動く（Python 3.9 以上）。追加の導入は要らない。

### 4. 渡す

1. `genogram.svg` を渡す。
2. スクリプトが表示した「図の下に添える注記」を、そのまま図の下に書く。言い換えない。

PNG が要ると言われたときだけ変換する。変換の前に、その環境に日本語のフォントがあるかを確かめる。無ければ文字が化けるので、SVG のまま渡してその旨を伝える。

## 直しの依頼を受けたとき

図の見た目を手で直さない。persons.json を直して描き直す。同じ記録からは同じ図が出るので、記録が図の原本になる。

## 個人の情報を扱うとき

家族関係は、それだけで人を特定できることがある。仮名にした図でも、渡す相手と保管の場所は依頼者が決める。Claude からは、図を外に送る操作をしない。

## 環境固有の設定

既定では設定は要らない。相談資料を扱う別のスキルや手順がある環境では、譲る相手と場所を `local.md` に書く（書き方は `local.md.example`）。`local.md` は配布物に入らない。

## 関連スキル

単体で動く。ほかのスキルは要らない。支援機関とのつながりの図や、相続関係の図は、このスキルの対象ではない。
