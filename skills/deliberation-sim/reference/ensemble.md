# アンサンブル運用 — 同じ議論をN回走らせて分布を取る

単一回の裁定より、10回の分布のほうが情報量が多い。ただし**正しく走らせなければ、10倍のコストで同じ答えを10回聞くだけになる。**

---

## 前提1 — temperature は使えない

temperature・top_p・top_k は Claude 4.7 以降のモデルではサポートされておらず、デフォルト以外の値を送ると 400 エラーになる。claude.ai の UI にも露出していない。
（出典：Claude Platform Docs / Using the Messages API。仕様は変わりうるので、実装前に https://docs.claude.com/en/docs_site_map.md から現行仕様を確認すること）

**これは制約というより設計の是正である。** 温度で作れる分散は「同じ論証を語彙だけ変えて繰り返す」ものになりやすい。欲しいのは論証そのものの分散であって、言い回しの分散ではない。

## 前提2 — 同一会話での反復は独立試行ではない

2回目以降は1回目を読んでいる。**必ず別セッションで走らせる。** 同一会話内で「もう一度」と繰り返した結果を分布として扱ってはならない。

## 前提3 — 収束は正しさの指標ではない

10回の一致は10人の専門家の一致ではない。全部同じモデルの、共通の事前分布から出ている。

> **10/10の収束が測っているのは「正しさ」ではなく「モデルの偏りの強さ」である。**

集計結果には必ずこの但し書きを付ける。付けずに提示すると、単一回の裁定より危険な代物になる。真の独立性に最も近づくのは、**異なるモデル（世代違い・他社モデル）で走らせること**である。可能ならrunの一部を別モデルに割り当てる。

---

## 起動判断 — そもそも回すべきか

回す前に判定する。**該当が3つ未満なら回さない。1本で足りる。**

| 条件 | 問い |
|---|---|
| 不可逆 | やり直しがきかないか |
| 外部で決着しない | 外から来る事実で答えが出ないか。出るとしても決定期限より後か |
| 見落としの損失が大きい | 思いつかなかった選択肢が、そのまま永久に失われるか |
| 一回性 | 同種の判断を繰り返さず、経験による補正が効かないか |

**該当例**：訴訟の主張構成、契約条項の設計、規程・制度の設計、組織再編、不可逆な設備投資。

**非該当例**：上場株の売買判断（可逆・分割可能・外部の観測で決着する）、繰り返し行う運用判断。

> **外から答えが来る課題に、内側の分布を並べても意味は薄い。** 決算発表1回の情報量のほうが、モデルを10回走らせるより桁違いに大きい。アンサンブルが出せるのはモデル内部の分布であって、外界の事実ではない。

---

## 適応的な回し方

**「10本」という固定数に根拠はない。** 分布を見るには少なすぎ、コストとしては大きい。固定10本は「10本走らせた」という手続き的な安心を与えるだけで、情報量に対して払うコストが最適化されていない。**割れた箇所に的を絞って追加する。**

### 段階1 — 標準4本

人格生成から自由に走らせる。集計して停止判定を行う。

**停止条件**（全部満たせばここで終える）
- 軸の選択が4本中3本以上で一致
- 結論が4本中3本以上で一致
- 確信度変化の主要ベクトルが再現している

満たせば追加6本は情報を増やさない。回さない。

### 段階2 — 割れ方に応じて追加

| 割れた箇所 | 追加する種 | 本数 | 狙い |
|---|---|---|---|
| 軸の選択が割れた | 軸の強制変更 | 2 | 標準runで選ばれなかった軸を必ず1本入れ、見落とし軸を検出 |
| 結論が割れた | 敵対 run | 2 | 多数結論を「採用禁止」として走らせ、多数結論の頑健性を試す |
| 同じ結論に別々の論拠で到達 | 賛否の割当反転 | 2 | 同じ論拠を反対の結論に奉仕させ、論拠と結論の癒着を剥がす |
| 少数結論が魅力的に見えた | その結論を出発点にした標準run | 1ー2 | 少数筋が再現するかを確かめる |

### 段階3 — 上限

**合計8本を超えたら止める。** それ以上は同じ事前分布の再サンプリングにすぎない。**分散が足りないのではなく、モデルが1つしかないことが限界である。** そこから先は別モデルで走らせるほかない。

---

## 集計する6指標

### 1. 軸の出現頻度
全runで選ばれた軸＝課題の骨格。1ー2本にしか出ない軸は、生成のゆらぎか**見落とされがちな貴重な観点**か。判別のため**少数軸は必ず個別に中身を見る**。頻度だけで切り捨てない。

### 2. 結論の分布
これが本当の出力。「全体6本中4本が条件付き実行、1本が見送り、1本が全面実行」という形で、**母数を明示して**提示する。単一の裁定に丸めない。

### 3. 確信度変化ベクトルの再現率
「人格Xが人格Yの発言で折れる」が全run中何回起きたか。**論証の強度の直接の指標。** 全runで再現する変節は、その論証が実質的に決着していることを示す。

### 4. 方向が逆転する人格
回によって上がったり下がったりする人格は、論拠が脆い箇所を指している。裁定書の「未決」欄に入れる候補。

### 5. 少数結論
1〜2回しか出ない筋は**別枠で全文保存する**。多数決で捨てない。見落とされた構成はここに現れる。

### 6. 敵対runの生存率
多数結論を禁じてもなお成立する構成が出るなら、多数結論は見かけほど強くない。逆に敵対runが軒並み破綻するなら、多数結論は頑健。

## 実装

### コスト設計
全10本でR0〜R5のフル散文を出すと高くつく。**散文の議事録はrun#1だけ。残り9本は構造化出力のみ**にする。集計は構造化データに対して機械的に行う。

### 出力スキーマ

```json
{
  "run_id": "run-03",
  "seed_type": "axis_forced",
  "typology": "実行判断型",
  "axes": ["効率", "危害の回避", "可逆性"],
  "personas": [
    {"id": "P1", "axis": "効率", "time": "短期", "stance": "実行側",
     "position": "賛成", "confidence_pre": 70, "confidence_post": 65,
     "falsifier": "…", "change_reason": "…"}
  ],
  "absent_party": "…",
  "issues": [{"id": "争点1", "label": "不確実性", "summary": "…"}],
  "verdict_type": "decision_rule",
  "verdict": "…",
  "dissent": ["…"],
  "observation_points": ["…"],
  "research_tasks": ["…"]
}
```

### 実行

各runは新しいセッションで起動する。Claude Code をヘッドレスで回す形が素直。

```bash
# ※ CLIのフラグは実行前に `claude --help` で確認すること
mkdir -p runs
for i in $(seq -w 1 4); do
  claude -p "$(cat seeds/standard.md)" > "runs/run-$i.json"
done
```

標準4本の集計後、**停止判定を行う**。満たさない項目に対応する種ファイル（`seeds/axis-forced.md` `seeds/inverted.md` `seeds/adversarial.md`）だけを生成して追加する。最初から全部の種を作らない。

集計は別セッションで、全runのJSONだけを読ませて行う。**議事録の散文を集計セッションに持ち込まない**（run#1の論調に引きずられるため）。

---

## 集計結果の提示形式

```
■ 分布サマリ
  結論：条件付き実行 3 / 見送り 1（標準4本）→ 停止条件未充足のため敵対 run 2本を追加
  ※ この分布は同一モデルの出力分布であり、専門家集団の見解分布ではない。
     収束の強さはモデルの偏りの強さも同時に反映している。

■ 全runで再現した論点（骨格）
■ 半数前後で割れた論点（未決。決定権者が引き受ける部分）
■ 少数結論（1〜2回。全文を別掲）
■ 敵対runの結果
■ 集計から導かれる観測点
```

**「少数結論」と「敵対runの結果」を省略した集計は、このスキルの目的を裏切る。** 多数派の答えが欲しいだけなら1回走らせれば足りる。10回走らせる理由は、少数の筋を拾うことにある。
