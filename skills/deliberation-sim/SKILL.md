# 熟議シミュレータ

## このスキルが解く問題

一人で考えると、自分が最初に思いついた筋を補強する材料ばかり集まる。人に相談しても、相手が一人なら視点も一つ。**決定の前に、異なる価値基盤を持つ複数の視点をぶつけ、どこで意見が変わりどこで変わらなかったかを記録する**——それを機械的な手順として実行する。

素朴に「賛成役と反対役を演じる」だけでは必ず失敗する。三つの失敗と、それぞれの対策がこのスキルの本体である。

| 失敗 | 症状 | 対策 |
|---|---|---|
| 論調の均質化 | 全員が同じ書き手なので推論が似通い、早すぎる合意に着地する | 人格を「結論」でなく**価値軸**で定義し、立論は人格ごとに**相互非参照**で書かせる。1つの会話で順に書く場合は台帳に「非独立立論」と記し、サブエージェントが使える環境では人格ごとに独立させる（→ PROTOCOL.md R1、環境固有の設定） |
| ストローマン化 | 反対役が想定内の弱い反対しか言わない | 反駁の前に**相手の最強版の再構成**を義務づける |
| 変節の演出化 | 「なるほど、考えを改めます」が礼儀として起き、なぜ変わったか検証できない | 開始時に各人格が**自分の意見が変わる条件**を先に宣言する |

三つ目が中核。反証条件を先に台帳へ書かせておけば、変節は演出ではなく「宣言済みの条件が満たされたので当然そうなった」という監査可能な事象になる。条件が満たされていないのに折れたら、不正な変節として差し戻す。

## 起動する / しない

**起動する**：複数の選択肢があり、どれを選ぶかで結果が変わり、まだ決めていない場面。

**起動しない**：
- 事実を尋ねられているだけの場面
- 既に決まっていて実行手順だけが必要な場面
- 緊急性が高く、議論の時間そのものが損失になる場面
- 決定権者が本人でなく、本人の希望を聞くべき場面（→ 意思決定支援の領域。混同しないこと）

**二段構え（明示語の有無で深さを変える）**：

| 入力 | 起動範囲 |
|---|---|
| 「議論させて」「賛否を洗い出して」等の明示語あり | 手順0から R5 までフル実行 |
| 明示語なしだが決定を求める問い（「どう考えればいい」「どう判断すべきか」「AかBか」等） | **軽量起動**。手順0と先行調査までを本スキルとして実行し、末尾で「R0.5 以降のフル熟議に進むか」を必ず確認する |

軽量起動でも直答で済ませてはならない。直答は決定主体・制約・未確認事実を曖昧にしたまま結論の傾きだけを出すので、後から監査できない。軽量起動の出力は「決定主体と制約」「先行調査タスク一覧」「フル熟議に進む場合の争点候補」の3点で構成する。

## 全体の流れ

```
手順0    決定の主体と制約を確定する ← ここが空欄なら裁定は出せない
先行調査 「この事実が判明すれば議論の大半が不要になる」項目を潰す
R0.5     課題から人格を生成し、ユーザーの承認を得る
R0       争点分解（以降の全発言に争点IDを紐づける）
R1       立論（相互非参照・確信度と反証条件を宣言）
R2       反駁（steelman義務）
R3       折衷設計（条件付き合意案のみ。中間値は禁止）
R4       再表明（確信度の再申告と変化理由）
R5       裁定（不可逆型は判決文、可逆型は決定ルール）
```

詳細は `PROTOCOL.md`。人格生成の材料は `reference/axes-and-typology.md`。複数回反復するなら `reference/ensemble.md`。

## 絶対禁則

1. **全員一致に至ったら失敗を疑う。** 悪魔の代弁者ラウンドを強制挿入して、なお一致するか確かめる。
2. **steelman の承認なき反駁は無効。** 相手が「その再構成でよい」と認めてから撃つ。
3. **R1で宣言した条件が満たされていない変節は差し戻す。**
4. **未確認の事実を推論で埋めない。** 埋めるなら `【仮定】` タグを必須にする。
5. **実在人物名を人格名に使わない。** 人格は価値軸の擬人化であって特定個人の代理ではない。「Aさんならこう言うはずだ」は、当人の検証を経ずに当人の見解として扱われる危険がある。
6. **決定権者の制約が未提供なら、裁定を出さずに枠だけ返す。** 埋め合わせで裁定を捏造しない。
7. **専門的助言に踏み込まない。** 医療・投資・個別法律相談の領域では、議論と観測点の提示までで止め、断定的な推奨を主文にしない。

## 出力物

- 人格カード一覧（R0.5 時点でユーザー承認を取る）
- 確信度台帳（pre / post）
- 議事録（争点IDつき）
- 裁定書 または 条件付き決定ルール
- **調査タスク一覧**（事実の争いはここへ落とし、議論を中断する）

人格カード・確信度台帳・反証条件・観測点は 1 つの台帳（`templates/LEDGER.md` の書式）にまとめる。台帳の渡し方は「環境固有の設定」に従う。

## 環境固有の設定

既定はこの表のとおり。同じディレクトリに `local.md` があれば、その記載で上書きする（無ければ何もしない）。

| 項目 | 既定（どの環境でも動く） | local.md で上書きできること |
|---|---|---|
| 台帳・報告の保存 | ダウンロード可能な Markdown ファイルとして返す。filesystem が使える環境で保存先を指定されればそこに書く | 保存先のパス |
| 立論の独立性 | 1つの会話で順に書く（台帳に「非独立立論」と記す） | サブエージェント並列（Claude Code の Agent ツール）の有効化 |
| 継続運用の観測点 | 本文に期日と判定手順を書いて人間に渡す | 期日管理ツール（thread 等）への書き出し |
| 先行調査の情報源 | Web 検索と会話内の情報 | 既存の知識ベース（wiki 等）を先に当てる |

`local.md.example` に上書きの書き方の例がある。claude.ai だけで使う場合は無視してよい。

## 関連スキル

| スキル | 関係 |
|---|---|
| `hypothesis-arena` | 姉妹スキル。「決める」はこちら、「なぜそうなのか／どの説が正しいか」を知るのはあちら。事実の争いが議論の中核だと判明したら移送する先で、逆にあちらの裁定者が「価値問題」と判定した探究はこちらへ送り返されてくる |

意思決定支援（決定権者が本人で、本人の希望を聞くべき場面）は本スキルとは別物である。本人の決定は本人のものであり、本スキルでシミュレートしてはならない（「起動しない」の 4 点目）。
