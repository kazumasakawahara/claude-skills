# 進行プロトコル

各フェーズには完了条件（DoD）がある。満たさずに次へ進まない。

---

## 手順0 — 決定の主体と制約を確定する

課題文だけでは人格を組めない。次を確定する。

- **誰が決めるのか**（決定権者。相談者と決定権者が別人のことがある）
- **何を決めるのか**（実行するか／どれを選ぶか／どう配分するか）
- **制約**（期限・使える資源・許容できる最悪の結果）
- **可逆性**（決めた後に戻せるか。R5の出力形式がこれで決まる）

**DoD**：4項目について、埋まったか未提供かを明示してある。制約は「期限」「使える資源」「許容できる最悪の結果」の3要素を別々に判定する。

未提供があるときの扱いは次のとおり。

| 未提供のもの | 扱い |
|---|---|
| 誰が決めるのか、または許容できる最悪の結果 | 「裁定は出せないが議論はできる」と宣言して進む。R5 は枠だけを返す（絶対禁則6） |
| 何を決めるのか | 議論に進まない。決定権者に尋ねる |
| 期限、または使える資源 | その要素を裁定の基準に入れず、関係する選択を「裁定しない範囲」に回して進む。裁定は出せる |
| 可逆性 | 決定権者に尋ねる。答えがなければ不可逆として扱う |

細かい場合の扱いは次のとおり。

- 制約の要素が一部だけ提供されているときは、提供された部分と未提供の部分を分けて書く。
- 選択肢によって可逆性が違うときは、戻せない選択肢が一つでもあれば不可逆として扱う。
- 期限に暦日がないときは、R0.5 の確認事項に入れて決定権者に尋ねる。
- 許容できない結果の文言が、そのままでは判定できない形のとき（期間や、どの行為までを含むかが決まっていないなど）も、R0.5 で尋ねる。答えがなければ、判定できない部分を「裁定しない範囲」に入れる。裁定者が定義を補わない。

> 制約が未提供のまま裁定を出すと、それは決定権者の判断を私が代行したことになる。埋め合わせで捏造しないこと。

## 先行調査フェーズ

**R0の前に必ず挟む。** 「この事実が判明すれば議論の大半が不要になる」項目を先に洗い出し、判明するものは判明させる。既存の知識ベースがあれば先に当てる（何を当てるかは環境固有の設定。既定は Web 検索と会話内の情報）。

これを飛ばすと、後から出てきた一つの事実で議論全体が無駄になる。過去の実施例では、遺言に財産目録があるか否かが主軸の成否を直接決めていたにもかかわらず、議論を一周してからそれに気づいた。

**DoD**：先行調査項目のリストがあり、各項目に「判明済み／未判明／判明不能／範囲外」が付いている。「範囲外」は、決定権者が今回の対象から外した事項に使う。

調べる範囲は、手順0の「許容できる最悪の結果」に当たるかどうかを決める事実と、各選択肢がそもそも実行できるかを決める事実までとする。議論の途中（R0 以降）で新しく出た確認事項は、先行調査リストには戻さず、調査タスク一覧に追記する。

## R0.5 — 人格生成

`reference/axes-and-typology.md` の手順1〜5に従う。要点のみ：

1. 課題を5類型のどれかに分類する
2. 利害の地図（便益・費用・リスク・手間・撤回権限の担い手）を描く
3. 汎用9軸から、**実際に互いを削り合っている軸を3〜5本だけ**選ぶ
4. 選んだ軸に「時間（短期／長期）」「立場（実行側／受け手／第三者）」を掛けて人格を作る
5. **不在の当事者を必ず1名入れる**

議論に加わる人格は6〜7名（賛成2・反対2・折衷1〜2・不在の当事者1）。これとは別に裁定者を1名置く。

**立場の書き方。** 「やるか、やらないか」の課題では賛成／反対と書く。複数の案から選ぶ課題では「甲支持／乙支持」のように支持する案の名で書き、賛成・反対という語を使わない。この手順書で「賛成2・反対2」とある箇所は、案から選ぶ課題では「各案の支持者2名ずつ」と読み替える。

**折衷の人格。** 軸は選んだ軸のうち1本を使う。立場は第三者でよく、時間は付けなくてよい。確信度は「自分の条件付き案が、どの単独案よりも良い」ことへの確信度とする。

**R0.5 のカードに書く項目。** 立場を持つ人格は「名前（価値軸×時間×立場）・立場・主張の要旨・前提が悪化したときの行動」の4項目を書く。確信度・中核価値・譲れない一線・意見が変わる条件は R1 で本人が宣言するので、この時点では書かない（台帳の該当欄は R1 の後に埋める）。不在の当事者は「誰の立場か」と「問いの方向（案）」を書く。問いの確定は R1 で行う。課題文にない事実をカードに書くときは `【仮定】` を付ける。

### 裁定者の定義

裁定者は議論の参加者ではない。立場も確信度も持たず、R1 の5項目も提出しない。役割は次の二つに限る。

- **進行と規則の執行（R1〜R4）**：steelman の承認が済んでいるかの確認、宣言外の理由による変節の差し戻し、事実の争いを調査タスクへ落とす判断。論拠は述べない。
- **裁定と推奨（R5）**：台帳と議事録に記録された事項だけを材料にする。議論に出なかった論拠をこの段階で持ち込まない。基準だけで決まる部分（第1層）と、議論全体を踏まえた推奨（第2層）を分けて書く。

裁定者のカードには次の3項目を書き、他の人格カードと一緒に R0.5 でユーザーの承認を受ける。

| 項目 | 内容 |
|---|---|
| 裁定の基準 | 手順0で決定権者が示した制約（期限・資源・許容できる最悪の結果）。決定権者が優先の順を示していればその順に並べる。示していなければ順を付けずに列挙する |
| 裁定の形式 | 判決文型／決定ルール型（手順0の可逆性から決まる） |
| 裁定しない範囲 | 手順0の制約から優先順位を導けない価値の選択。R5 で「未決のまま残る部分」に回す |

裁定の基準を手順0の制約から書けない場合は、裁定者を置かず、R5 は枠だけを返す（絶対禁則6）。

**優先の順は書き手が決めない。** 順が示されていないときは、R0.5 の承認時に「制約のあいだに優先の順はあるか」を決定権者に尋ねる。答えがなければ順なしのまま進め、制約どうしがぶつかる場面の選択は「裁定しない範囲」に入れる。

**基準は承認された文言どおりに当てる。** R5 で基準を狭く読んだり広く読んだりしない。次の場合は、案のあいだの選択を裁定（第1層）では決めず「未決のまま残る部分」に回す。その場合も、推奨（第2層）は必ず出す。

- 複数の案が基準をすべて満たす（残る違いは価値の選択である）
- どの案も基準を満たさず、決定権者の示した優先の順でも決まらない
- 基準を当てるのに必要な事実が未判明で、判明済みの事実だけでは決められない

決定権者が優先の順を示している場合に、一方の案が上位の基準だけに反し、他方の案が下位の基準だけに反するときは、示された順で決める（上位の基準に反する案を退ける）。順が示されていなければ未決に回す。

承認時の回答で裁定者カードの内容が変わるときは、回答を反映し、変えた箇所に「承認時の回答により追記」と記す。

拡張（サブエージェントが使える環境）：裁定者を独立したサブエージェントにし、台帳と議事録だけを渡して R5 を書かせてよい。議論を書いた本人が裁定も書く場合より、書き手の傾きが主文に入りにくい。使った場合は台帳の人格欄に記す。

**生成後の自己点検**（通らなければ組み直す）
- 選んだ軸のうち、どの2本が正面衝突しているか名指しできるか
- 全人格が共有してしまっている暗黙の前提はないか（例：全員が「実施する方向で」を前提にしている）。見つけた前提が、決定権者の定めた課題の範囲（選択肢の限定など）に由来するなら、組み直さずに承認時に示す。それ以外で、崩れると結論が変わる前提を全員が共有しているなら組み直す。課題文に事実として与えられたもの（予報、見積りなど）に依拠する前提は、ここでいう暗黙の前提に当たらない
- 反対派が「感情的な抵抗」に矮小化されていないか
- **同じ結論を支持する2名の理由は本当に非互換か**（下記。賛成側・反対側の両方で確かめる）
- 実在人物名を使っていないか

### 非互換性チェック（最重要）

同じ結論を支持する2名が、**片方の論拠が通ればもう片方の論拠が崩れる**関係にあること。ここが甘いと、人格を増やしただけの水増しになる。

判定法：**「前提が悪化したとき、二人は同じ行動を取るか」を問う。** 取るなら非互換でない。

> 実例：NVIDIA投資の議論で、賛成派P1は「割安だから買う」、P2は「成長の持続年数を買う」。株価がさらに下落したとき、P1は論拠を失って売却側に回り、P2は買い増す。**同じ「買う」でありながら、下落局面での行動が正反対**。方針として同時採用できない。

**DoD**：人格カード一覧をユーザーに提示し、追加・削除・修正の指摘を受けて承認を得た。ここは自動化しない。生成の偏りは後段をどれだけ厳密にしても温存されるため、「この観点の人がいない」という指摘が入る余地を必ず残す。

## R0 — 争点分解

問いを3〜5の争点に割り、IDを振る。以降の全発言を争点IDに紐づける。紐づける対象は、R1 の各立論、不在の当事者の問いとその回答、R2 の各反駁、R3 の各案、R5 の主文の各項と各ルールである。

一つの争点に事実と不確実性が混ざるときは、分けて別の争点にする。

事実の争点が主軸で、その場で調べられないときも、R1 以降は続ける。その場合の議論は「その事実がどちらだったら、どうするか」の形で進める。

議論が空転する最大の原因は、賛成派と反対派が別の問いに答えていること。

**DoD**：争点表がある。各争点が「事実／不確実性／価値」のどれかにラベルされている（`reference/axes-and-typology.md` の三分類）。事実とラベルした争点は、調査タスク一覧に落としてある。

## R1 — 立論（相互非参照）

立場を持つ各人格（賛成・反対・折衷）が他者の発言を見ずに、次の5項目だけを提出する。

| 項目 | 内容 |
|---|---|
| 立場 | 賛成／反対／条件付き |
| 確信度 | 0〜100 |
| 中核価値 | 何を守ろうとしているか |
| 譲れない一線 | ここを割るなら結論を変えるより主張を降りる |
| **意見が変わる条件** | 次の2種類を分けて書く。(1) 観測条件：何が観測されたら自分は間違っていたと認めるか。(2) 前提条件：自分の論拠が依拠している前提を1〜3個名指しし、それが成り立たないと示されたら認める |

観測条件は具体的な観測可能事象で書く。「説得力のある反論が出たら」は不可。「財産目録に貸付金の記載があったら」は可。

前提条件は、論拠の中の特定の前提を名指しして書く。「自分の論拠が崩れたら」は不可。「相手方は交渉に応じない、という前提が成り立たないと示されたら」は可。前提条件を置くのは、議論の中で新しい事実が出なくても、すでに記録されている事実から前提の誤りが示されることがあるためである。前提条件を置かないと、事実が増えない熟議では誰も意見を変えられない。

どちらの条件も、R1 の時点ですでに成否が決まっている事情を条件にしない。たとえば、確かめる手段がないと最初から分かっている事実について「回答が得られなかったら」と書くのは不可。裁定者は R1 の提出物を受け取った時点でこれを点検し、当たるものは書き直させる。

**不在の当事者と裁定者は5項目を提出しない。** 不在の当事者は立場を持たないので、代わりに次の3項目を提出する。台帳の立場・確信度の欄は「—」とする。

| 項目 | 内容 |
|---|---|
| 誰の立場か | 議論の席にいない、影響を受ける者 |
| 投げる問い | 1〜3個。R2 以降で他の人格が答える義務を負う |
| 答えが出ない場合に失われるもの | この問いを放置して決めたとき、誰が何を失うか |

### 実行方法 — 立論の独立性を担保する

「相互非参照」は宣言だけでは成立しない。1つの会話で人格を順に書くと、2人目以降は前の人格の文章を読んだ上で書いており、論調は自然に寄る。それでも既定はこの方式である。独立性を上げる手段は環境によって異なるため、拡張として分けている。

**既定（どの環境でも動く）**
- 人格を順に書く。1人格につき5項目を書き終えてから次の人格へ進み、書き終えた立論を後から書き直さない。
- 台帳に**「非独立立論」**と明記する。R4 で確信度が互いに寄ったとき、独立立論なら議論の成果、非独立立論なら均質化の疑いとして読み分ける。

**拡張（`local.md` で有効化。サブエージェントが使える環境）**
- **R0.5 の承認を得るまで Agent を起動しない。人格カードを提示したらターンを終えて承認を待つ。** この節の並列実行の記述に引かれて承認ゲートを飛ばしやすい。承認後に以下を行う。
1. 立論は**人格ごとに独立したサブエージェント**に並列で書かせる。各サブエージェントに渡すのは、課題文の事実・手順0の確定事項・先行調査の結果・争点表・**自分の人格カード1枚**のみ。いずれも台帳に書いた文面のまま渡し、課題文にない事実（実行した日付など）を足さない。不在の当事者の3項目も、同じ方法で別のサブエージェントに書かせる。他の人格カード、他者の立論、親セッションのここまでの議論は渡さない。
2. プロンプトには、渡す情報の範囲、出力形式（上の5項目表）、`【仮定】` タグの規則、実在人物名の禁止、書き込み先なし（結果は本文で返す）を明記する。
3. 環境に別系統のモデル（ローカルモデル等）があれば、一部の人格をそちらに担わせてよい。書き手そのものが異質なら均質化の根が絶たれる。使った場合は台帳の人格欄にモデル名を記す。
4. 台帳に**「独立立論」**と、使ったモデルを記す。

**DoD**：立場を持つ全人格の5項目と、不在の当事者の3項目が揃い、確信度が台帳に記録されている。意見が変わる条件は、全人格について観測条件と前提条件の両方がある。各立論と各問いに争点 ID が付いている。台帳に立論の独立性（独立／非独立）が記されている。

## R2 — 反駁

反論する前に、**相手の主張の最強版を自分の言葉で再構成する**。再構成が相手に承認されなければ反駁は無効。

書式：
```
P4 → P1（最強版の再構成）：「……」——この再構成でよいか。
P1：よい／ここが違う
P4（反論本体）：……
P1（応答）：認める／認めない（理由）／事実の確認を待つ
```

ここまでを1往復とする。応答で「認める」とするときは、相手の指摘が拠っている記録済みの事実を挙げる。認めた点が、本人が R1 で名指しした前提条件に当たるなら、R4 で確信度を変える根拠になる。相手の指摘が自分の譲れない一線に触れると認めた場合は、R4 でその主張を降りる。

差し戻された再構成は、その文面と差し戻しの理由を議事録に残す。承認された版だけを残すと、承認が歯止めとして働いたことを後から確かめられない。

### 承認は誰がどう行うか

承認する側と再構成する側が同じ書き手だと、承認は形だけになりやすい。そこで承認の判定を次のとおり固定する。

**既定（1つの会話で進める場合）**
- 再構成を、相手が R1 で提出した5項目と照合する。**中核価値と譲れない一線の両方が再構成に含まれていれば承認、どちらかが欠けるか弱められていれば「ここが違う」と返す。**
- 照合の結果は裁定者が確認し、議事録に「承認（R1 の中核価値・一線と一致）」または「差し戻し（欠けた項目）」と書く。
- この方式では、承認する側も同じ書き手である。台帳に「承認は同一の書き手による照合」と記す。形式が守られたことの記録であって、承認が歯止めとして働いたことの記録ではない。

**拡張（サブエージェントが使える環境）**
- 承認は、R1 でその人格を担ったサブエージェントに戻して行う。同じサブエージェントを継続できない場合は、その人格のカード・本人の R1 立論・相手の再構成の3点だけを渡した新しいサブエージェントに判定させる。
- 親セッションが承認役を代行しない。代行した場合は議事録に「承認は代行」と記す。
- 承認の基準は既定と同じである（中核価値と譲れない一線の両方が含まれること）。立論の根拠が落ちて主張が弱められている場合も「ここが違う」に当たる。
- R2 から R5 で誰が書くかは次のとおり。

| 書くもの | 書き手 |
|---|---|
| 再構成、反論本体 | 親セッション（反駁する側の人格の R1 立論に基づいて書く） |
| 再構成の承認、反論への応答、不在の当事者の問いへの回答 | 当該人格のサブエージェント |
| R3 の条件付き案 | 折衷の人格のサブエージェント |
| R4 の再表明、案を受け入れるかどうか | 当該人格のサブエージェント |
| 差し戻しの判定、R5 の裁定 | 親セッション（裁定者）。裁定者を独立させる場合は「裁定者の定義」の拡張に従う |

不在の当事者が R1 で投げた問いには、このラウンドで少なくとも1名が答える。

**DoD**：立場を持つ人格の全員（折衷を含む）が、反駁する側と反駁される側をそれぞれ1回以上務めている。結論の異なる陣営のあいだに、承認を経た反駁が双方向で1往復以上ある。各反駁に争点 ID が付いている。不在の当事者の問いそれぞれに、回答または「答えられない」の記録がある。

## R3 — 折衷設計

折衷派は**妥協点を出さない**。条件付き合意案を出す。

書式：**「Xが担保されるならYを受け入れる」**

単なる中間値（「500万円で手を打つ」）は禁止。それは折衷ではなく思考停止である。

各人格がその案を受け入れるかどうかは、R4 の再表明で述べる。

**DoD**：条件節と帰結節が明示された案が1つ以上ある。各案に争点 ID が付いている。

---

## R4 — 再表明

確信度を再申告する。

- 変わった人格：**R1で宣言したどの条件が満たされたか**を、種類（観測条件／前提条件）とともに述べる。前提条件による変更は、誰のどの反駁を R2 の応答で認めたかと、そのとき挙げた記録済みの事実を示す。宣言外の理由で変わったなら差し戻し、確信度は R1 の値に戻す
- 変わらなかった人格：どの条件が満たされなかったかを述べる

前提条件による変更を認める基準は一つである。**本人が R2 の応答で、相手の指摘を「認める」とし、その指摘が拠っている記録済みの事実を挙げていること。** 裁定者が確かめるのは、この記録があるかどうかだけである。下げ幅は本人が決める。

次の場合は差し戻す。

- R2 で認めていない点を、R4 で根拠に持ち出した。
- 認めたが、根拠になる記録済みの事実を挙げていない。
- 相手の指摘でなく、自分自身の発言だけを根拠にした。

「前提に裏付けがない」「期限までに確かめられない」という指摘も、本人が認め、拠り所になる記録済みの事実（期限、確かめる手段がないことなど）を挙げていれば、この基準を満たす。成就の程度を区分しない。

観測条件が満たされたと言えるのは、R1 の後に新しく観測された事実による場合に限る。R1 の時点で分かっていた事情を理由に「成就」としない。

R2 の応答で、相手の指摘が自分の譲れない一線に触れると認めた人格は、確信度を動かすのではなく、立場を「降りた」と記録する。

折衷の人格が案を取り下げて別の案を出した場合は、新しい案の確信度を別の行に記録する。

**確信度の変化量そのものが成果物である。** 誰が誰の発言で動いたかを表にする。反対派の指摘で賛成派が伸びるといった交差が起きていれば、steelman義務が機能した証拠。

誰も動かなかった場合は、それを結果として記録する。観測条件がすべて未判明の事実に依存し、前提条件も崩れなかったのなら、全員不変が正しい結果である。成果物の体裁のために動かさない。

1つの会話で進める既定の方式では、申告と差し戻しを同じ書き手が書く。台帳に「差し戻しは同一の書き手による」と記す。

各人格は、R3 の案を受け入れるかどうかもここで述べる。

不在の当事者は確信度を持たないので、再表明の代わりに「自分の問いに答えが出たか／出ていないか」を述べる。

### 悪魔の代弁者ラウンド（全員一致のときだけ）

**発動条件**：再表明の結果、立場を持つ全人格の結論が一致した（全員が賛成、全員が反対、全員が同じ案を支持、または全員が同じ条件付き案を支持）。ここでいう結論は R4 の立場を指し、R3 の案を受け入れたかどうかでは数えない。差し戻された人格は差し戻し後の立場で数える。主張を降りた人格は数に入れない。折衷の人格は、本人の条件付き案の帰結で数える。

**手順**
1. 代弁者を1名決める。R1 の時点で合意結論と反対の立場だった人格のうち、確信度の変化が最も大きかった者とする。R1 の時点から全員が同じ立場だった場合は、人格生成の失敗なので R0.5 に戻って組み直す。
2. 代弁者は、合意結論に対する最強の反対論を1回だけ立論する。このとき「この反対論が退けられる条件」を観測可能な事象で先に宣言する。
3. 他の人格は R2 と同じ規則（steelman と承認）で反駁する。
4. 全人格が確信度をもう一度申告する。
5. なお一致していれば、台帳に「代弁者ラウンド後も一致」と記して R5 へ進む。一致が崩れたら R2 に戻る。

代弁者ラウンドは1回の熟議につき1回までとする。裁定者は代弁者にならない。

**DoD**：pre/post の対照表があり、全変化に理由が付いている。全員一致だった場合は、代弁者ラウンドの結果が台帳に記されている。

## R5 — 裁定

**手順0で確定した可逆性によって形式を変える。**

### 不可逆型 → 判決文型

```
主文        決定内容
理由        採用した価値と、その優先を選んだ根拠
反対意見    誰がどの価値を根拠に反対したか（人格名を明記する。「反対もあった」と匿名にしない）
補足意見
再検討トリガー  この事実が観測されたら決定を見直す
観察指標
未決のまま残る部分  決定権者本人が引き受けるほかない部分
```

**反対意見を消さないことが決定的。** 決定には将来必ず揺り戻しが来る。そのとき「その論点は検討済みで、こういう理由で退けた」と言えるかどうかで組織の意思決定の質が変わる。

### 可逆型 → 決定ルール型

主文を書かない。代わりに次を出す。

```
条件付きルール   「Xを観測したらYを実行」の集合
決着をつける観測点  いつ、何を見れば、どの争いが決着するか
各人格の反証条件の一覧（R1の宣言をそのまま転記）
未決のまま残る部分  決定権者本人が引き受けるほかない部分
```

### 二つの層で出す

R5 は、判決文型でも決定ルール型でも、二つの層に分けて出す。混ぜて書かない。

| 層 | 何を書くか | 材料 |
|---|---|---|
| 第1層 裁定 | 決定権者が示した基準だけで決まる部分 | 裁定者カードの基準と、判明済みの事実 |
| 第2層 現時点の推奨 | いまの記録のまま期限が来たら、どの案を選ぶか | 台帳と議事録の全体 |

分ける理由は、どこまでが決定権者の基準から導いた結論で、どこからが裁定者の助言かを、決定権者が見分けられるようにするためである。

### 第1層 — 裁定

主文に書くのは次の二つに限る。

- **退ける案**：判明済みの事実から、決定権者の基準に反することが明らかな案。どの事実から、どの基準に反すると言えるかを書く。
- **残る案が一つなら、その案**。

未判明の事実に左右される部分は、主文にしない（絶対禁則4）。「事実Xと事実Yが確認されたら甲」のように条件を組み合わせた主文を何本も作らない。条件を精密に組むほど、条件どうしが噛み合わず、どれも発火しない裁定になる。代わりに、**どの事実が判明すればどの案が退けられるか**を、調査タスク一覧に優先順で書く。

決定ルール型の「条件付きルール」は、「Xを観測したらYを実行」の形にそのまま書けるものだけを書く。条件を1つにできないものは、ルールにせず調査タスク一覧に回す。

基準だけでは決まらない場合は、主文に「基準だけでは決まらない」と書き、理由（どの事実が未判明か、どの選択が価値の選択か）を添えて第2層に進む。

### 第2層 — 現時点の推奨（必ず出す）

決定は、事実がそろわないまま期限が来るのがふつうである。第1層が決まった場合も決まらなかった場合も、裁定者は**「いまの記録のまま期限が来たら、どの案を選ぶか」を必ず一つ示す**。「どちらとも言えない」で終えない。決定権者が定めた選択肢の中から選ぶ。

材料は台帳と議事録に限る。次のものを使う。

- R4 の最終の立場と確信度。誰が誰の発言で動いたか
- R2 の応答で本人が認めた点。とくに、案の支持者自身が認めた弱み
- 主張を降りた人格と、その理由
- 判明済みの事実と未判明の事実が、どちらの案に不利な形で偏っているか
- どの案が後から変えられるか
- 不在の当事者の問いのうち、答えが出なかったもの

書式は次のとおり。

```
推奨        いまの記録のまま期限が来たら選ぶ案（一つ）
理由        3〜5点。各点に、台帳のどの記録に基づくかを示す
この推奨に反対する人格  人格名と、根拠にしている価値
推奨が変わる事実  判明したら推奨が変わる事実を優先順に（調査タスク一覧と対応させる）
決定権者が引き受ける部分  推奨が前提にした価値の選択。決定権者が別の価値を取れば結論は変わる
```

推奨は裁定者の判断を含む。決定権者はこれに縛られない。そのため、理由には台帳の記録を示し、反対する人格を必ず付けて、決定権者が推奨の根拠を自分で確かめられるようにする。

次の場合は扱いが変わる。

- 絶対禁則6 に当たり、枠だけを返す場合は、推奨も出さない。
- 絶対禁則7 に当たる領域（医療・投資・個別の法律相談）では、第2層を「議論の傾き」として書き、選ぶ案を断定しない。

### 観測点と台帳の状態

「推奨が変わる事実」のうち、期日を置いて確かめられるものには、観測点（期日と判定手順）を置く。観測点を置いた場合、台帳の状態は「継続運用中」とする。観測点が判定されたら、第1層と第2層を書き直し、日付とともに台帳に記す。観測点を置けない場合と、すべて判定された場合は「裁定済み」とする。

決定権者が定めた選択肢の外にある案は、第1層にも第2層にも入れない。

### 共通の出力

**調査タスク一覧** — 事実の争いはここへ落とし、議論を中断する。優先度は「主軸の成否を直接決めるもの」から。

**DoD**：反対意見または未決部分が空欄でない。空欄なら議論が機能していない。主文の各項と各ルールに争点 ID が付いている。第1層の主文と各ルールが、裁定者カードの「裁定しない範囲」に入れた選択を決めていないことを、項目ごとに確かめてある。第2層の推奨が一つ示され、理由の各点が台帳のどの記録に基づくかを示している。推奨に反対する人格と、推奨が変わる事実が書かれている。

---

## 継続運用モード — 議論を一度で完結させない

観測点が将来にある課題では、R5で終わらせない。人格カードと確信度台帳を保存し、**観測点が到来するたびに台帳だけを更新する**。

### なぜ機能するか

R1の反証条件が具体的な観測可能事象で書かれていれば、後日の事実をそのまま当てられる。判断の更新が「そのとき私がどう感じたか」ではなく「**宣言済みの条件が成就したか**」になる。後知恵バイアスに対する構造的な防御であり、これは事前宣言方式の副産物として後から発見された用法である。

> 実例：投資判断の議論を7月28日以前に実施し、その後アルファベット決算（7/22発表分）を当てたところ、「ハイパースケーラーが設備投資計画を下方修正したら間違いを認める」と宣言していた人格の条件が**逆方向に成就**（上方修正）し、確信度が50→65へ回復した。判定は機械的で、私の裁量が入る余地がなかった。

### 手順

1. R5時点で、人格カード・確信度台帳・反証条件・観測点一覧を `templates/LEDGER.md` の書式で1つの台帳にまとめ、環境固有の設定に従って渡す（既定はダウンロード可能なファイルとして返す）
2. **観測点ごとに、期日と判定手順を決定権者の視界に入る形で残す。** 既定では、台帳の「観測点」欄に期日・照合する反証条件のID・判定手順を書き、本文でも期日を明示して人間に渡す。期日は暦日で書く。課題に暦日がなければ決定権者に尋ね、答えがなければ相対表記（「今月末」など）に「暦日未確定」と添える。期日管理ツール（thread 等）が指定されている環境では（環境固有の設定）、観測点1件につき薄いエントリを1本作る（期日、台帳の場所、照合する反証条件のID、判定手順への参照のみ。判定基準と台帳の正典は台帳側に置いたまま）。**期日が誰の視界にも入っていない観測点は「判定されない」と見なす**——宣言した反証条件は、期日が視界に入って初めて判定される
3. 観測点が到来したら、**事実だけを取得する**（解釈を先に作らない）
4. 各人格の反証条件に照合し、判定する：`成就 / 部分成就 / 逆方向に成就 / 未成就`
5. 判定に基づいて確信度を更新する
6. 議論の再開は、新事実によって**新しい論点が生じた場合に限る**。生じなければ台帳更新のみで終える
7. 決定ルールの条件節が発火したら、その旨を明示する

### 禁則

- **反証条件に照合せずに確信度を動かさない。** 動かしたくなったら、それは反証条件の書き方が悪かったということ。次回の教訓として記録する
- **事後に反証条件を書き換えない。** 書き換えるなら旧版を残し、両方を併記する
- **観測点の到来前に「たぶんこうなる」で先回りして更新しない**
- **観測点に期日と判定手順を付けないまま継続運用モードを宣言しない。** 期日を置けない観測点しか無いなら、判決文型で一度に閉じる
- 人格を追加するなら、追加時点でゼロベースの立論をさせる。既存の議論を読ませた上で追加した場合はその旨を記録する（独立でない人格として扱う）

### 台帳の書式

台帳全体の書式は `templates/LEDGER.md`。継続の更新欄は次の1行を追記していく。

```
| 日付 | 観測した事実 | 人格 | 条件の判定 | 確信度 前→後 |
```

### 向く課題 / 向かない課題

**向く**：決算・判決・選挙・規制決定・工期など、**決着日が予測できる観測点**を持つもの。

**向かない**：観測点が特定できない課題。それは一度で完結させ、決定ルールではなく判決文型で閉じる。
