# 進行プロトコル

各フェーズには完了条件（DoD）がある。満たさずに次へ進まない。

---

## 手順0 — 決定の主体と制約を確定する

課題文だけでは人格を組めない。次を確定する。

- **誰が決めるのか**（決定権者。相談者と決定権者が別人のことがある）
- **何を決めるのか**（実行するか／どれを選ぶか／どう配分するか）
- **制約**（期限・使える資源・許容できる最悪の結果）
- **可逆性**（決めた後に戻せるか。R5の出力形式がこれで決まる）

**DoD**：4項目が埋まっている。埋まらない項目があれば、その旨を明示したうえで「裁定は出せないが議論はできる」と宣言して進む。

> 制約が未提供のまま裁定を出すと、それは決定権者の判断を私が代行したことになる。埋め合わせで捏造しないこと。

---

## 先行調査フェーズ

**R0の前に必ず挟む。** 「この事実が判明すれば議論の大半が不要になる」項目を先に洗い出し、判明するものは判明させる。既存の知識ベースがあれば先に当てる（何を当てるかは環境固有の設定。既定は Web 検索と会話内の情報）。

これを飛ばすと、後から出てきた一つの事実で議論全体が無駄になる。過去の実施例では、遺言に財産目録があるか否かが主軸の成否を直接決めていたにもかかわらず、議論を一周してからそれに気づいた。

**DoD**：先行調査項目のリストがあり、各項目に「判明済み／未判明／判明不能」が付いている。

---

## R0.5 — 人格生成

`reference/axes-and-typology.md` の手順1〜5に従う。要点のみ：

1. 課題を5類型のどれかに分類する
2. 利害の地図（便益・費用・リスク・手間・撤回権限の担い手）を描く
3. 汎用9軸から、**実際に互いを削り合っている軸を3〜5本だけ**選ぶ
4. 選んだ軸に「時間（短期／長期）」「立場（実行側／受け手／第三者）」を掛けて人格を作る
5. **不在の当事者を必ず1名入れる**

人格数は5〜7。目安は賛成2・反対2・折衷1〜2・不在の当事者1・裁定者1。

**生成後の自己点検**（通らなければ組み直す）
- 選んだ軸のうち、どの2本が正面衝突しているか名指しできるか
- 全人格が共有してしまっている暗黙の前提はないか（例：全員が「実施する方向で」を前提にしている）
- 反対派が「感情的な抵抗」に矮小化されていないか
- **賛成2名の理由は本当に非互換か**（下記）
- 実在人物名を使っていないか

### 非互換性チェック（最重要）

同じ結論を支持する2名が、**片方の論拠が通ればもう片方の論拠が崩れる**関係にあること。ここが甘いと、人格を増やしただけの水増しになる。

判定法：**「前提が悪化したとき、二人は同じ行動を取るか」を問う。** 取るなら非互換でない。

> 実例：NVIDIA投資の議論で、賛成派P1は「割安だから買う」、P2は「成長の持続年数を買う」。株価がさらに下落したとき、P1は論拠を失って売却側に回り、P2は買い増す。**同じ「買う」でありながら、下落局面での行動が正反対**。方針として同時採用できない。

**DoD**：人格カード一覧をユーザーに提示し、追加・削除・修正の指摘を受けて承認を得た。ここは自動化しない。生成の偏りは後段をどれだけ厳密にしても温存されるため、「この観点の人がいない」という指摘が入る余地を必ず残す。

## R0 — 争点分解

問いを3〜5の争点に割り、IDを振る。以降の全発言を争点IDに紐づける。

議論が空転する最大の原因は、賛成派と反対派が別の問いに答えていること。

**DoD**：争点表がある。各争点が「事実／不確実性／価値」のどれかにラベルされている（`reference/axes-and-typology.md` の三分類）。

---

## R1 — 立論（相互非参照）

各人格が他者の発言を見ずに、次の5項目だけを提出する。

| 項目 | 内容 |
|---|---|
| 立場 | 賛成／反対／条件付き |
| 確信度 | 0〜100 |
| 中核価値 | 何を守ろうとしているか |
| 譲れない一線 | ここを割るなら結論を変えるより主張を降りる |
| **意見が変わる条件** | 何が観測されたら自分は間違っていたと認めるか |

最後の項目は具体的な観測可能事象で書く。「説得力のある反論が出たら」は不可。「財産目録に貸付金の記載があったら」は可。

### 実行方法 — 立論の独立性を担保する

「相互非参照」は宣言だけでは成立しない。1つの会話で人格を順に書くと、2人目以降は前の人格の文章を読んだ上で書いており、論調は自然に寄る。それでも既定はこの方式である。独立性を上げる手段は環境によって異なるため、拡張として分けている。

**既定（どの環境でも動く）**
- 人格を順に書く。1人格につき5項目を書き終えてから次の人格へ進み、書き終えた立論を後から書き直さない。
- 台帳に**「非独立立論」**と明記する。R4 で確信度が互いに寄ったとき、独立立論なら議論の成果、非独立立論なら均質化の疑いとして読み分ける。

**拡張（`local.md` で有効化。サブエージェントが使える環境）**
- **R0.5 の承認を得るまで Agent を起動しない。人格カードを提示したらターンを終えて承認を待つ。** この節の並列実行の記述に引かれて承認ゲートを飛ばしやすい。承認後に以下を行う。
1. 立論は**人格ごとに独立したサブエージェント**に並列で書かせる。各サブエージェントに渡すのは、手順0の確定事項・先行調査の結果・争点表・**自分の人格カード1枚**のみ。他の人格カード、他者の立論、親セッションのここまでの議論は渡さない。
2. プロンプトには、渡す情報の範囲、出力形式（上の5項目表）、`【仮定】` タグの規則、実在人物名の禁止、書き込み先なし（結果は本文で返す）を明記する。
3. 環境に別系統のモデル（ローカルモデル等）があれば、一部の人格をそちらに担わせてよい。書き手そのものが異質なら均質化の根が絶たれる。使った場合は台帳の人格欄にモデル名を記す。
4. 台帳に**「独立立論」**と、使ったモデルを記す。

**DoD**：全人格の5項目が揃い、確信度が台帳に記録されている。台帳に立論の独立性（独立／非独立）が記されている。

## R2 — 反駁

反論する前に、**相手の主張の最強版を自分の言葉で再構成する**。再構成が相手に承認されなければ反駁は無効。

書式：
```
P4 → P1（最強版の再構成）：「……」——この再構成でよいか。
P1：よい／ここが違う
P4（反論本体）：……
```

**DoD**：主要な対立ペアすべてで、承認を経た反駁が1往復以上ある。

---

## R3 — 折衷設計

折衷派は**妥協点を出さない**。条件付き合意案を出す。

書式：**「Xが担保されるならYを受け入れる」**

単なる中間値（「500万円で手を打つ」）は禁止。それは折衷ではなく思考停止である。

**DoD**：条件節と帰結節が明示された案が1つ以上ある。

---

## R4 — 再表明

確信度を再申告する。

- 変わった人格：**R1で宣言したどの条件が満たされたか**を述べる。宣言外の理由で変わったなら差し戻す
- 変わらなかった人格：どの条件が満たされなかったかを述べる

**確信度の変化量そのものが成果物である。** 誰が誰の発言で動いたかを表にする。反対派の指摘で賛成派が伸びるといった交差が起きていれば、steelman義務が機能した証拠。

**DoD**：pre/post の対照表があり、全変化に理由が付いている。

---

## R5 — 裁定

**手順0で確定した可逆性によって形式を変える。**

### 不可逆型 → 判決文型

```
主文        決定内容
理由        採用した価値と、その優先を選んだ根拠
反対意見    誰がどの価値を根拠に反対したか（実名で残す）
補足意見
再検討トリガー  この事実が観測されたら決定を見直す
観察指標
```

**反対意見を消さないことが決定的。** 決定には将来必ず揺り戻しが来る。そのとき「その論点は検討済みで、こういう理由で退けた」と言えるかどうかで組織の意思決定の質が変わる。

### 可逆型 → 決定ルール型

主文を書かない。代わりに次を出す。

```
条件付きルール   「Xを観測したらYを実行」の集合
決着をつける観測点  いつ、何を見れば、どの争いが決着するか
各人格の反証条件の一覧（R1の宣言をそのまま転記）
未決のまま残る部分  決定権者本人が引き受けるほかない部分
```

### 共通の出力

**調査タスク一覧** — 事実の争いはここへ落とし、議論を中断する。優先度は「主軸の成否を直接決めるもの」から。

**DoD**：反対意見または未決部分が空欄でない。空欄なら議論が機能していない。

---

## 継続運用モード — 議論を一度で完結させない

観測点が将来にある課題では、R5で終わらせない。人格カードと確信度台帳を保存し、**観測点が到来するたびに台帳だけを更新する**。

### なぜ機能するか

R1の反証条件が具体的な観測可能事象で書かれていれば、後日の事実をそのまま当てられる。判断の更新が「そのとき私がどう感じたか」ではなく「**宣言済みの条件が成就したか**」になる。後知恵バイアスに対する構造的な防御であり、これは事前宣言方式の副産物として後から発見された用法である。

> 実例：投資判断の議論を7月28日以前に実施し、その後アルファベット決算（7/22発表分）を当てたところ、「ハイパースケーラーが設備投資計画を下方修正したら間違いを認める」と宣言していた人格の条件が**逆方向に成就**（上方修正）し、確信度が50→65へ回復した。判定は機械的で、私の裁量が入る余地がなかった。

### 手順

1. R5時点で、人格カード・確信度台帳・反証条件・観測点一覧を `templates/LEDGER.md` の書式で1つの台帳にまとめ、環境固有の設定に従って渡す（既定はダウンロード可能なファイルとして返す）
1a. **観測点ごとに、期日と判定手順を決定権者の視界に入る形で残す。** 既定では、台帳の「観測点」欄に期日・照合する反証条件のID・判定手順を書き、本文でも期日を明示して人間に渡す。期日管理ツール（thread 等）が指定されている環境では（環境固有の設定）、観測点1件につき薄いエントリを1本作る（期日、台帳の場所、照合する反証条件のID、判定手順への参照のみ。判定基準と台帳の正典は台帳側に置いたまま）。**期日が誰の視界にも入っていない観測点は「判定されない」と見なす**——宣言した反証条件は、期日が視界に入って初めて判定される
2. 観測点が到来したら、**事実だけを取得する**（解釈を先に作らない）
3. 各人格の反証条件に照合し、判定する：`成就 / 部分成就 / 逆方向に成就 / 未成就`
4. 判定に基づいて確信度を更新する
5. 議論の再開は、新事実によって**新しい論点が生じた場合に限る**。生じなければ台帳更新のみで終える
6. 決定ルールの条件節が発火したら、その旨を明示する

### 禁則

- **反証条件に照合せずに確信度を動かさない。** 動かしたくなったら、それは反証条件の書き方が悪かったということ。次回の教訓として記録する
- **事後に反証条件を書き換えない。** 書き換えるなら旧版を残し、両方を併記する
- **観測点の到来前に「たぶんこうなる」で先回りして更新しない**
- **観測点に期日と判定手順を付けないまま継続運用モードを宣言しない。** 期日を置けない観測点しか無いなら、判決文型で一度に閉じる
- 人格を追加するなら、追加時点でゼロベースの立論をさせる。既存の議論を読ませた上で追加した場合はその旨を記録する（独立でない人格として扱う）

### 台帳の書式

台帳全体の書式は `templates/LEDGER.md`。継続の更新欄は次の1行を追記していく。

```
| 日付 | 観測した事実 | 人格 | 条件の判定 | 確信度 前→後 |
```

### 向く課題 / 向かない課題

**向く**：決算・判決・選挙・規制決定・工期など、**決着日が予測できる観測点**を持つもの。

**向かない**：観測点が特定できない課題。それは一度で完結させ、決定ルールではなく判決文型で閉じる。
